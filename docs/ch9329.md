# CH9329 serial HID backend

KV can drive a WCH CH9329 UART-to-USB-HID bridge directly from Crystal. No Python helper or HTTP API is required.

Example:

```sh
sudo ./bin/kv -ch9329-device=/dev/ttyUSB0
```

The default serial configuration is **9600 8N1**. A different supported baud rate can be selected with:

```sh
sudo ./bin/kv --ch9329-device=/dev/ttyUSB0 --ch9329-baud=115200
```

The web UI's "Input 1"–"Input N" buttons (and `POST /api/switch`) send a
configurable key sequence to the attached KVM switch. The sequence is set with:

```sh
sudo ./bin/kv --ch9329-device=/dev/ttyUSB0 --ch9329-kvm-input-key-sequence="ctrl+ctrl+#"
```

The sequence is a `+`-separated list of keys. Each token is sent as an
independent press + release. The literal token `#` is replaced by the
requested input slot, so `ctrl+ctrl+#` produces `Ctrl`, `Ctrl`, then the
slot number.

The number of input buttons rendered in the UI (and accepted by the API) is set
with `--ch9329-kvm-input-count`:

```sh
sudo ./bin/kv --ch9329-device=/dev/ttyUSB0 --ch9329-kvm-input-count=4
```

This renders "Input 1" through "Input 4" on both the desktop and mobile pages.

KV uses the CH9329 protocol mode:

- `0x02` — 8-byte USB boot keyboard report
- `0x05` — relative mouse report
- `0x04` — absolute mouse report

Frames use `57 AB 00 CMD LEN DATA... CHECKSUM`, where the checksum is the low byte of the sum of all preceding frame bytes.

The keyboard path sends USB HID usage IDs, not translated characters. Therefore the keyboard layout remains the responsibility of the operating system attached to the CH9329, which is what allows US and Canadian-French keyboards to behave correctly.

The CH9329 backend is mutually exclusive with KV's USB gadget HID backend. Video, audio, mass storage, and Ethernet functionality are otherwise unchanged.
